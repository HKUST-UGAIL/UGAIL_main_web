# UGAIL 官网设计方案

日期：2026-10-28

状态：用户已确认原方案；本文已按用户后续要求修订首页布局与 What We Do 栏目。X 账号按用户要求暂用占位符，真实成员、成果和联系资料由用户后续提供。

## 1. 目标与参考

在 `UGAIL_main_web` 建立 UGAIL 的公开介绍网站，访客可以了解团队、项目、论文成果和近期活动，并找到参与途径。

参考来源：

- https://uiuc-conversational-ai-lab.github.io ：参考其 Home、Team、Projects、Publications、Blogs、Updates 等学术网站栏目和内容组织；不复制其团队与研究成果。
- 本地 `USTLabSpace-main`：参考 `app/globals.css`、`app/page.tsx`、`components/layout/site-header.tsx` 的色彩、排版、校园图片横幅和卡片语言。

现有项目只有 README，没有需要兼容的应用、数据或部署设置。

## 2. 方案选择

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| Next.js + TypeScript + Tailwind，静态导出（推荐） | 与 USTLabSpace 技术体系接近；组件可复用；可部署 GitHub Pages 或静态托管 | 需要 Node.js 构建 |
| Astro 静态网站 | 浏览器脚本较少，适合内容站 | 与现有 Next.js 参考项目的组件不能直接复用 |
| Jekyll | 与参考学术站及 GitHub Pages 原生流程接近 | 前端组件和交互维护方式与现有项目不同 |

推荐首个方案，以内容展示为核心。成员、项目、论文、新闻通过仓库中的类型化数据文件维护。

## 3. 网站结构

| 页面 | 路径 | 首版内容与行为 |
| --- | --- | --- |
| Home | `/` | 宽幅左栏：图片在上、介绍在下；窄右侧栏：X 账号小卡片在上、最新动态在下 |
| Team | `/team/` | 按角色展示成员；有资料时提供头像、研究兴趣、个人主页链接 |
| What We Do | `/what-we-do/` | 展示团队正在做的项目和参与的活动；按 Projects / Activities 筛选；支持独立详情页 |
| Publications | `/publications/` | 按年份分组；关键词搜索和年份筛选；有来源时显示论文、代码与 BibTeX 操作 |
| Updates | `/updates/` | 新闻、活动和文章列表；按类别筛选；支持独立详情页 |
| Join us | `/join/` | 参与方式、适合人群和已有的公开联系途径 |

全站共享品牌导航、移动端菜单、页脚、当前页状态及自定义 404 页面。

参考站的 Blogs 合并到 Updates 的文章分类。会议截止日期日历不列入首版；后续有明确需求和数据来源时增加。

## 4. 视觉设计

### 品牌与配色

- 主色沿用 USTLabSpace 的深蓝 `#003c71`，首屏使用 `#0c2e45`。
- 正文色 `#10233f`，辅助文字 `#5b6b81`，页面底色 `#f7f9fc`。
- 白色内容表面、`#d7e1ee` 细边框、18px 卡片圆角和轻阴影。
- 青绿色和浅鼠尾草绿用于栏目标签和局部强调；少量金黄色用于重点信息。
- 使用清晰的无衬线字体、大标题、足够留白；内容最大宽度约 1200–1280px。
- 首版使用文字标识 UGAIL，不擅自扩展缩写或制作官方校徽。

### 首页布局

1. 顶部导航：UGAIL 品牌、页面入口、Join us 按钮。
2. 桌面主体左右排布：左栏占主要宽度，右栏为约 270–304px 的窄侧栏。
3. 左栏上方直接展示图片，不叠加大标题或深色遮罩；下方显示简洁的欢迎标题、分段介绍及 Team / What We Do 链接。
4. 右栏最上方显示小型 X 账号卡片。账号尚未提供，按用户要求使用 `@your_handle` 占位符；不生成虚假账号链接。以后配置 `site.xHandle` 即可启用真实关注链接。
5. X 卡片下方显示 Latest updates，按日期倒序最多展示六条，并提供全部动态和详情链接；无真实动态时显示简洁空状态。这是维护于网站的动态，并非嵌入的实时 X 信息流。
6. 手机端先显示图片和介绍，再显示 X 卡片和动态；全站共享页脚。

栏目名称选择 **What We Do**，直接表达“我们在做什么”，同时覆盖项目和活动。内容分为 **Projects** 与 **Activities**，替换原 Research 页面。
校园图片可从现有 `USTLabSpace-main/public/figures/HKUST.jpeg` 复用，准确标注为校园景观，不作为实验室团队照片。

### 响应式与可访问性

- 首页在 850px 以上为宽主栏加窄侧栏，850px 及以下依次纵向排列；其他列表页按可用宽度自适应，不产生页面横向滚动。
- 移动导航具备可访问名称、展开状态、Escape 关闭和清晰的焦点样式。
- 语义化标题、跳转正文链接、键盘可用的筛选与按钮、足够的文字对比度。
- 图片设置替代文字和尺寸；首屏主图优先加载，其余图片按需加载。
- 尊重系统减少动画偏好。

## 5. 内容与语言

用户已确认首版以英文为主，与所给学术参考站一致。导航、页面文案、筛选控件和空状态均使用英文；首版不增加语言切换功能。

只将仓库已有或用户确认的信息作为正式资料。UGAIL 全称、具体组织归属、研究方向、成员名单、项目、论文和联系方式目前没有资料支持，不生成虚构名称、身份、发表记录、统计数字或邮箱。

内容缺失时使用简洁的真实空状态；相关内容模块可隐藏。供开发参考的内容样例单独存放并明确说明，不进入正式展示数据。用户以后可以直接修改内容文件并加入图片，无须编辑页面组件。

用户提供资料后的内容模型：

- `site`：名称、介绍、首页图片及替代文字、可选 X 用户名、公开联系信息与外部链接。
- `people`：姓名、角色、简介、头像、主页链接、显示顺序。
- `initiatives`：标题、摘要、Project / Activity 类别、主题、图片、详情正文、外部资源链接。
- `publications`：标题、作者、年份、会议或期刊、论文链接、可选代码链接与 BibTeX。
- `updates`：标题、日期、类别、摘要、可选正文与外部来源。

可选字段缺失时隐藏对应操作；不显示空链接或只有外观的按钮。

## 6. 实现边界

- Next.js App Router、TypeScript 和 Tailwind；选择实施时稳定且兼容的版本并提交锁文件。
- 构建时生成全部页面，详情页使用可枚举的内容数据生成静态路由。
- 筛选、搜索、移动导航等局部交互使用客户端组件；页面主体保持静态渲染。
- 内容模型和渲染组件分离；组件负责导航、页面标题、内容卡片、筛选控件、空状态和页脚。
- 链接和资源路径统一支持可配置站点子路径，兼容 GitHub Pages 项目地址及自定义域名根路径。
- 提供适配静态托管的图片方案，避免依赖运行时图片优化服务。
- 提供页面标题、description、Open Graph 基础信息；只有真实域名已配置时生成正式 canonical、sitemap 与 robots 配置。
- 配置可供用户后续启用的 GitHub Pages 构建部署工作流；本次开发不包含远端发布。
- 提供 README：本地运行、内容编辑、图片替换、构建、站点子路径和部署说明。

首版范围为公开介绍站，数据通过 Git 维护。账号、数据库和后台编辑系统不属于本方案。

## 7. 验证与验收

- 安装依赖后完成 TypeScript、代码检查和生产静态构建。
- 通过浏览器检查首页及全部栏目页；验证移动端与桌面布局。
- 验证导航、移动菜单、项目与动态详情、搜索和筛选、空结果提示及 404。
- 对有数据的论文验证链接与 BibTeX 操作；对空内容验证不会出现虚构记录或无效操作。
- 使用隔离的测试数据验证交互，不将测试数据作为官网正式内容。
- 检查根路径与 `/UGAIL_main_web/` 子路径下的页面、静态资源及直接访问详情页。
- 检查浏览器控制台错误、断链、键盘焦点和图片替代文字。
- 记录可重复执行的验证命令与结果，交付本地预览启动方式。
